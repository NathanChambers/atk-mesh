# Mesh modeling workflow

## Session scope and iteration

- Pick one work mode from the user's request before planning commands. Geometry modeling, texturing, and export or integration are separate sessions of work even when they use the same saved workspace. Keep the pass in that mode. Change modes when the user explicitly requests it.
- After rough blockout, do a primary-form refinement pass before secondary details. Work on the largest unresolved interfaces first. Use shared profiles, connected recesses, and deliberate seams. Review the neutral mesh at player height and from an oblique angle until it reads as one designed object and its separable parts read at the intended distance.
- Plan a small reviewable change, batch independent commands, and wait for returned IDs, evidence, or revisions before dependent work. Reuse valid captures and measurements for untouched interfaces. Check changed mounts and one representative case of an identical linked fit before widening the audit.
- Deliver the saved native workspace and the views needed for the user's next decision. A completed modeling or texturing pass can leave export validation pending. Export and independently reimport only when the user requests an export or is ready to integrate the asset.

- Generating inside an existing object requires explicit `mode:"append"` or `mode:"replace_region"`. Query components before appending; replace a named region when iterating the same part. Bounds overlap warnings are candidates, not surface-intersection findings.
- Distinguish object joining, face deletion, bridging and welding. `object_join` combines ownership only. `delete_faces` requires an explicit orphan-vertex choice. Preview a multi-step repair with protections, read the final report, then commit the accepted `preview_id` with its revision. A changed revision requires a fresh preview.
- Scope `inspect_defects` to the changed surfaces and their neighbors for local overlap checks. Use `measure_clearance` for unsigned surface separation and `inspect_volume` for protected-box intrusion. Check moving interfaces in representative poses. Read completeness and limitations. Record intentional contact only for explicit face or region pairs with reasons.
- Save fixed camera presets for player height and comparison angles. A written brief can use camera-only `review_run` presets with scoped dimensions, clearances, and protected volumes. Include wireframe, tessellation, or defect reports where the planned edit needs them. Reference presets can also render overlays. Change framing through `review_update` and read the evidence before assessing. Use named regions and recorded construction parameters where practical.
- Plan edge flow around curves, recesses, seams, and parts expected to move or change. A flat static cap can use a planar n-gon. Compare clean `topology` and `tessellation` captures before accepting a complex panel or preparing export. Use `retriangulate_region` for a planar patch that needs a better fill. Rebuild warped or edit-sensitive surfaces with deliberate loops and validate one likely future edit.
- Name critical regions in the accepted primary assessment and read the detail-stage topology prompts. Reuse symmetric profiles or verify mirrored counterparts. Run a representative edit in a preview or a copy, and record what it preserves before delivery.
- Read `instancing_review` at blockout before building repeated parts, including repeats within a floor or assembly. Plan each master and its placements, build the master once, then batch direct `object_instance` calls. For repeated layouts, reuse placement offsets at each floor or assembly origin. Use separate masters for geometry variants. Review equivalent independent copies for `object_link_instance`. Verify placement in a fixed view and preview a representative master edit.
- Verify camera framing with a capture before running a new preset with clearance or defect checks. Reuse a successful transaction preview receipt while its revision is current.
- For a connected patch edit, use `inspect_patch` to get the directed perimeter and `replace_patch` to keep it fixed while changing the interior. Use transaction boundary guards and fixed-camera preview images to check that the edit preserves surrounding features.

- Use the native mesh CLI for geometry creation and localized edits. Do not replace a mesh with a modeling script. Preserve existing objects and stable IDs where practical.
- Use the project-root viewer to discover meshes. Run a separate API-only editor with `mesh-server --workspace PATH --port PORT` for each mesh being edited. Send commands and batches to that editor's port.
- Batch prepared sequences with `mesh-cli --port PORT --batch --input FILE` or pipe a JSON array into `mesh-cli --port PORT --batch`. One invocation sends up to 1,024 commands in one request and returns one JSON line per attempted command. The server runs them in order and stops at the first failure. Earlier edits remain applied. Send separate requests when a later command depends on a returned ID, revision, or review result. Read the `batch-commands` help topic for examples.
- Begin each modeling task with `workflow_status`. Every project starts with pending intent, reference, primary-form, view, and export-validation requirements.
- Read `part_review` before blockout. Record the major parts, the views in which they control the silhouette, and their important interfaces with `workflow_part_plan`. Bind parts to objects or collections as you build them. Query the plan for the objects involved before fitting or revising an interface.
- Record a target `profiles` entry for each silhouette-driving view. Describe taper, section changes and edge character, distinguish observed and inferred shape, and check the targets with actual views or measurements before accepting primary forms.
- For a written design, assess the reference requirement with `basis:"shape_brief"` after saving its part plan. Review captures and measurements against the brief.
- Use `workflow_stage` to enter `primary`, `detail`, and `complete`. Refresh checks affected by the edit before completion. The `export` command separately requires export validation when an integration pass begins.
- Follow the commands and reading prompts in `requirements_missing` responses. Read actual images/reports before recording assessments. Command success is not proof of visual accuracy.
- For inapplicable requirements, use `workflow_waive` with a specific reason. An object waiver does not waive the project default. Never waive solely to unblock progress.
- Register approved references; generated hidden views are interpretations. Compare primary forms against the reference before detailing. Check distinct views for thickness and clearances.
- For reference matching, register named image landmarks and mesh bindings with `reference_landmarks`. Calibrate framing with trusted anchors using `fit_reference`, then inspect independent regions with `project_reference` and overlay captures. Image targets are original-image pixels, not crop-local pixels. Do not deform trusted geometry to compensate for a bad camera. Single-view residuals do not establish depth or material accuracy.
- Register capture evidence using returned trace session/event. Refresh checks invalidated by relevant geometry changes before advancing/exporting.
- Treat concepts and drawings as approximate observations: perspective and local proportions may be inconsistent. Use plausible camera bounds and trusted anchors, inspect independent regions, and preserve coherent geometry rather than forcing every residual to zero. Document ambiguous or inferred structure.
- Keep `project.json`, `workflow.json`, resources and `sessions/` together in the model workspace. Recordings include workflow decisions and explicit exemptions.
